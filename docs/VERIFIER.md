# The browser verifier

`attackledger.com/verify` checks an AttackLedger report in the browser, with the same checks,
verdicts and messages as `tools/verify_report.py`. The app's Verify tab uses the same code.

## Pieces

| File | What it is |
|---|---|
| `web/src/verify_report.ts` | The verifier: a port of `tools/verify_report.py`, check by check and message by message. Used by the public page and by `web/src/Verify.tsx`. |
| `web/src/tsa_roots.ts` | The roots in `tools/tsa-roots/`, generated by `tools/build_verify.sh`. |
| `web/src/verify_page.html`, `web/src/verify_page.ts` | The public page: template and script. |
| `site/verify.html` | The built page, one self-contained file (script, styles, fonts and roots inline). Generated; do not edit. |
| `tools/build_verify.sh` | Builds `site/verify.html` and `web/src/tsa_roots.ts`, and writes the page's CSP with the hashes of its inline script and style. |
| `tools/build_pages.sh` | Copies the page into the Pages build, serves the same CSP as a header for `/verify`, and refuses a page whose hashes do not match. |
| `tools/verifier_equivalence/` | The equivalence tests: `run.sh`, `run.mjs`, `cases.json`, `make_fixtures.py` and `fixtures/`. |

## Why a port and not a rewrite

The report's hashes are over Python's `json.dumps` output, so the module reads JSON as Python
does (ints and floats stay apart, `1e400` is infinity, NaN is read) and writes it the same way
(sorted keys by code point, Python's float repr, `ensure_ascii` for the manifest). Where the
script raises on a missing key or a wrong type, the module raises the same kind of error, so a
malformed report fails, or cannot be checked, where the script's would.

## Cryptography

WebCrypto checks SHA-2, ECDSA P-256 and P-384, and RSA PKCS #1 v1.5. The script's own checks on
points, lengths and padding run first, so both refuse the same malformed inputs. Ed25519 uses
WebCrypto where the browser has it (Chrome and Edge 137+, Firefox 129+, Safari 17+). Elsewhere it
uses a port of the script's own RFC 8032 code, which is in the module and no new dependency.
Keys and R points of small order always go to the port: OpenSSL's WebCrypto refuses some
signatures that the script's equation accepts (measured; see the equivalence table).

## Nothing is uploaded

The page's policy is `default-src 'none'; connect-src 'none'`, with hashes for its one inline
script and one inline style, `font-src data:` and `img-src data:`, `form-action 'none'`,
`base-uri 'none'` and Trusted Types with no policy (so no `innerHTML`). It is in a meta tag, so
a saved copy keeps it, and in the `/verify` header. Cloudflare Pages joins that header with the
site-wide one, which makes two policies that the browser both enforces. CSP cannot stop a top-level
navigation, so the script never navigates. That can be checked by reading it: it is about
2,000 lines, unminified, in the page.

## Equivalence tests

```bash
cd web && npm ci && cd ..
tools/verifier_equivalence/run.sh                    # needs python3 and node
tools/verifier_equivalence/run.sh --markdown out.md  # also writes the table
```

The runner bundles the module and runs both verifiers on every report in `cases.json`. These are
the sample report, the demo exports, genuine reports from the server and mutated copies. It
compares each check's verdict and the whole output, line for line, with Ed25519 checked both
through WebCrypto and through the fallback. Then it compares the building blocks one by one:
Ed25519, P-256, RSA and P-384 vectors, including forged padding and torsion points; canonical
JSON; ISO times; base64. Exit code 0 means no difference.

To remake the fixtures from the current server (for example after a format change):

```bash
docker run --rm --user 1000:1000 -e HOME=/tmp -v "$PWD":/w -w /w/server \
  --entrypoint python attackledger-api:latest /w/tools/verifier_equivalence/make_fixtures.py
```

When `verify_report.py` changes, change `web/src/verify_report.ts` the same way, add a case to
`cases.json`, then run `tools/build_verify.sh` and `run.sh`.
